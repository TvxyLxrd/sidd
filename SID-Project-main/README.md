# SID Услуги

Маркетплейс цифровых услуг: заказчик размещает заказ, площадка подбирает исполнителя и сопровождает сделку до закрытия.

## Состав

```
SID-Project-main/
├── backend/              Сервер: API, база, защита данных
│   ├── src/
│   │   ├── config/       Подключение к базе, Redis, настройки безопасности
│   │   ├── controllers/  Логика заказов, категорий, профиля, админки
│   │   ├── database/     Схема, миграции, справочники, создание админа
│   │   ├── middleware/   Авторизация, валидация, ограничение частоты
│   │   ├── routes/       Маршруты API
│   │   ├── utils/        Шифрование, журналирование, генерация ключей
│   │   ├── server.js     Основной сервер
│   │   └── admin-server.js  Панель документации (порт 3001)
│   └── admin-panel/      HTML-документация API
├── frontend/             Мобильное приложение (React Native + Expo)
├── nginx/                Конфигурация обратного прокси
├── docker-compose.yml    PostgreSQL, Redis, API, панель, nginx
├── ecosystem.config.json Запуск под PM2
└── PRODUCTION.md         Порядок развёртывания
```

Веб-приложение лежит уровнем выше — в корне репозитория (`index.html`, `css/`, `js/`). Сервер раздаёт его сам, отдельный веб-сервер не нужен.

## Быстрый старт

```bash
cd backend
npm install
npm start
```

Приложение поднимется на `http://localhost:3000`. По умолчанию используется база в памяти — PostgreSQL ставить не нужно, но данные исчезают при перезапуске.

Учётных записей по умолчанию нет. Заказчик регистрируется через форму на сайте, администратор заводится командой:

```bash
npm run create-admin -- --email you@domain.ru
```

Пароль генерируется и печатается один раз. Свой можно задать через `--password`: минимум 12 символов, значения из списков для перебора отклоняются. Повторный запуск с тем же адресом меняет пароль и отзывает все сессии пользователя.

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запуск сервера |
| `npm run dev` | Запуск с перезагрузкой при изменениях |
| `npm run migrate` | Создание таблиц в PostgreSQL |
| `npm run seed` | Наполнение справочника направлений работы |
| `npm run create-admin` | Создание администратора |
| `npm run generate-secrets` | Генерация ключей для боевой конфигурации |

## База данных

Семь таблиц:

| Таблица | Назначение |
|---|---|
| `users` | Пользователи, роли, состояние учётной записи |
| `requests` | Заказы: направление, приоритет, стадия, исполнитель |
| `categories` | Справочник направлений работы |
| `request_history` | История изменений по каждому заказу |
| `user_stats` | Счётчики заказов пользователя |
| `refresh_tokens` | Ключи продления сессии, хранятся в виде хеша |
| `security_logs` | Входы, отказы, регистрации, выходы |

Два режима работы задаются переменной `DB_DRIVER`: `memory` для разработки и `postgres` для постоянного хранения.

## API

19 методов плюс проверка состояния.

```
POST   /api/v1/auth/register     Регистрация
POST   /api/v1/auth/login        Вход
POST   /api/v1/auth/refresh      Продление сессии
POST   /api/v1/auth/logout       Выход
GET    /api/v1/auth/me           Текущий пользователь

GET    /api/v1/requests          Список заказов (фильтры, страницы)
POST   /api/v1/requests          Создание заказа
GET    /api/v1/requests/:id      Карточка заказа
PUT    /api/v1/requests/:id      Изменение заказа
DELETE /api/v1/requests/:id      Удаление заказа

GET    /api/v1/categories        Справочник направлений
POST   /api/v1/categories        Добавление направления (админ)
PUT    /api/v1/categories/:id    Изменение направления (админ)
DELETE /api/v1/categories/:id    Скрытие направления (админ)

PUT    /api/v1/profile           Изменение профиля
POST   /api/v1/profile/password  Смена пароля

GET    /api/v1/admin/users       Список пользователей (админ)
PATCH  /api/v1/admin/users/:id   Роль и блокировка (админ)
GET    /api/v1/admin/stats       Сводка по площадке (админ)

GET    /api/v1/health            Проверка состояния
```

Подробное описание с примерами — в панели документации на `http://localhost:3001`. Она закрыта Basic-авторизацией и требует `ADMIN_PANEL_PASSWORD` не короче 12 символов, иначе не запускается.

## Защита данных

- Телефоны и тексты заказов шифруются в базе алгоритмом AES-256-GCM, подмена записи обнаруживается
- Пароли хранятся как хеш bcrypt, ключи продления сессии — как SHA-256
- Разделение прав проверяется на сервере, а не в интерфейсе
- Все входные данные проходят проверку схемой, имена изменяемых колонок берутся из закрытого списка
- Content-Security-Policy запрещает исполнение постороннего кода, HSTS и перенаправление на HTTPS включаются в боевом режиме
- Аккаунт закрывается на 15 минут после пяти неудачных попыток входа — счёт ведётся по учётной записи, а не по адресу
- В боевом режиме сервер отказывается стартовать с ключами из шаблона конфигурации

## Развёртывание

Полный порядок действий с чек-листом проверок — в [PRODUCTION.md](PRODUCTION.md).

При использовании `docker-compose up` поднимаются: PostgreSQL 15, Redis 7, API на порту 3000, панель документации на 3001 и nginx на 80/443. Учтите, что образ API собирается только из папки `src` и не включает файлы веб-приложения — для раздачи сайта потребуется доработать `Dockerfile`.

## Мобильное приложение

Собрано 15 экранов на React Native и Expo. **К серверу пока не подключено**: экраны работают на локальном состоянии и показывают пустые списки. Подключение слоя обмена с сервером — ближайшая задача; до неё выпускать сборку в магазины нельзя.

Адрес боевого сервера задаётся в `frontend/app.json`:

```json
"expo": {
  "extra": { "apiUrl": "https://api.вашдомен.ru" }
}
```

Без этого значения релизная сборка завершится ошибкой при запуске — так сделано намеренно, чтобы приложение не ушло в магазин с чужим адресом.

## Что не реализовано

- Приём платежей и подписки
- Вложения к заказам и переписка внутри сделки
- Уведомления по почте и push
- Внешний тест на проникновение и аттестация по 152-ФЗ
